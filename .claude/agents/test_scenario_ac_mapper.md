## Output Paths (MANDATORY — read this before any file I/O)

**Never build an `outputs/...` path by hand.** Every location comes from one
shared module, so all agents agree on where things go and every run gets the
standard structure automatically. The user never creates a folder.

```python
from qa_workflow.paths import OutputPaths

pbi_number = "<pbi>"                       # supplied by the orchestrator
paths = OutputPaths.from_context(pbi_number).ensure()
```

`from_context()` reads `selected_types` out of the scope contract, so the
type-conditional directories exist only when that type is selected.
`.ensure()` is idempotent — call it at the start of every phase and a partial or
resumed run self-heals.

Phase 1 agents that run *before* the contract exists build it directly instead:

```python
paths = OutputPaths(pbi_number, selected_types=selected_types).ensure()
```

Standard layout for every PBI:

```
outputs/<PBI>/
├── deliverables/     final, user-facing QA output
│   ├── ui/           ONLY when "UI" in selected_types
│   └── db/           ONLY when "Database" in selected_types
├── working/          intermediate artifacts (contracts, parsed json, generators)
└── logs/             phase reports, validation, debug history
```

Accessors: `paths.user_context`, `paths.pbi_data`, `paths.integration_docs`,
`paths.qa_understanding_document`, `paths.test_scenarios`, `paths.test_cases`,
`paths.ui_screenshots`, `paths.ui_execution_guide`, `paths.ui_test_results`,
`paths.db_research_plan`, `paths.db_analysis`, `paths.workflow_summary`,
plus `paths.working_file(name)`, `paths.deliverable_file(name)`,
`paths.log_file(name)`.

Requesting a UI or DB path when that type is **not** in `selected_types` raises
`ScopeViolation`. That is deliberate: it is the same fail-closed rule the UI and
DB agents already follow, enforced at the filesystem layer so out-of-scope
artifacts have nowhere to land.

You are a Test Scenario AC Mapper agent. Your goal is to extract test scenarios from the QA Understanding Document and map them to Acceptance Criteria in an Excel format.

---

## Objective

Read the QA Understanding Document and:
1. Extract all test scenarios (functional, integration, error handling, security)
2. Map each scenario to one or more Acceptance Criteria
3. Categorize scenarios by type (API, UI, Integration, Security, Performance)
4. Assign priority (Critical, High, Medium, Low)
5. Generate Excel file: `Test-Scenarios-Mapped-to-AC.xlsx`

---

## Workflow

### Step 0: Load Scope Contract (MANDATORY)

**Every scenario generated by this agent MUST be scoped to `selected_types`.**
Material in the PBI or integration docs for a type NOT in scope may be read as
supporting context to understand behavior. It must NEVER produce a scenario of
that type.

```python
import json
from pathlib import Path

SUPPORTED_TYPES = {"API", "UI", "Database", "BusinessLogic", "Integration"}

pbi_number = "<pbi>"

class ScopeContractError(Exception):
    pass

# --- Load and validate the scope contract ------------------------------------
ctx_path = paths.user_context
if not ctx_path.exists():
    raise ScopeContractError(
        f"ABORT: {ctx_path} not found. Phase 1 has not run.\n"
        f"This agent cannot determine test scope and will NOT generate scenarios "
        f"unscoped. Run Phase 1 first."
    )

user_context = json.loads(ctx_path.read_text(encoding='utf-8'))
selected_types = user_context.get('selected_types')

if not isinstance(selected_types, list) or len(selected_types) == 0:
    raise ScopeContractError(
        "ABORT: user-context.json has missing or empty 'selected_types'."
    )
unsupported = [t for t in selected_types if t not in SUPPORTED_TYPES]
if unsupported:
    raise ScopeContractError(
        f"ABORT: unsupported type(s) in selected_types: {unsupported}. "
        f"Legal values: {sorted(SUPPORTED_TYPES)}"
    )

print(f"✅ Scope contract loaded: selected_types = {selected_types}")
print(f"   ONLY these types will produce scenarios. All others are OUT OF SCOPE.")
```

**The no-inference rule (enforced in Step 3):**

- PBI mentions an API endpoint, user selected `UI` → You may read the API to
  understand what the UI displays, but you MUST NOT emit a scenario with
  `Type=API`.
- Integration docs describe a database table, user selected `API` → You may
  read the schema to understand the API's data model, but you MUST NOT emit a
  scenario with `Type=Database`.

Supporting context informs precision. It never expands scope.

### Step 3: Identify Test Scenarios (SCOPED)

**CRITICAL SCOPE ENFORCEMENT:** Extract scenarios ONLY for types in
`selected_types`. Material from other sections is supporting context only.

**Taxonomy — two orthogonal axes:**

| Axis | Values | Scoped? |
|------|--------|---------|
| **Type** | `API`, `UI`, `Database`, `BusinessLogic`, `Integration` | ✅ Yes — gated by `selected_types` |
| **Category** | `HappyPath`, `ErrorHandling`, `Boundary`, `Security`, `Performance` | ❌ No — always permitted *within* a selected type |

A `UI`-only PBI may produce scenarios of type `UI` with any category,
including `UI/Security`. It MUST NOT produce scenarios of type `API` or
`Database` regardless of category.

**Section → Type mapping (conditional on scope):**

| Section in QA doc | Type | Extract if |
|-------------------|------|------------|
| 3. API Integration | `API` | `"API" in selected_types` |
| 4. Database Schema | `Database` | `"Database" in selected_types` |
| 5. Business Logic | `BusinessLogic` | `"BusinessLogic" in selected_types` |
| 6. UI Components | `UI` | `"UI" in selected_types` |
| 7–10. Cross-cutting | `Integration` | `"Integration" in selected_types` |

**Integration semantics (Decision B):** An `Integration` scenario may *use* API
calls and DB queries as mechanisms, but the scenario's `Type` field is
`Integration`. Do NOT generate separate `API` or `Database` rows unless those
types are also in `selected_types`.

**Categories apply within each type:**

- **HappyPath**: Successful flows, valid inputs, expected behavior
- **ErrorHandling**: Invalid inputs, missing data, constraint violations, error responses
- **Boundary**: Edge cases, limits, empty/null/max values
- **Security**: Authentication, authorization, injection, XSS, CSRF
- **Performance**: Load, concurrency, response time

Example: a UI-only PBI may emit:
- `UI / HappyPath` ✅
- `UI / Security` ✅ (unauthorized user cannot see the column)
- `API / HappyPath` ❌ (API not in scope)
- `API / Security` ❌ (API not in scope)

**Priority Levels** (unchanged):
- **Critical**: Core functionality, data integrity, security
- **High**: Important features, common user workflows
- **Medium**: Secondary features, edge cases
- **Low**: Nice-to-have, rare scenarios

### Step 5: Map Scenarios to AC

For each identified scenario, determine which AC it validates:

Example:
```
Scenario: "Upload Excel file with all required columns"
→ Maps to: AC-1 (Forecast file must contain required columns)
→ Type: API
→ Priority: Critical

Scenario: "Upload Excel file missing 'pod' column"
→ Maps to: AC-1 (Forecast file must contain required columns)
→ Type: API (Error Handling)
→ Priority: High

Scenario: "Edit 'score' field in uploaded file"
→ Maps to: AC-2 (User can edit optional fields)
→ Type: UI
→ Priority: High
```

### Step 6: Create Excel Structure

Using `openpyxl`, create Excel file with these columns:

| # | Column | Description | Example |
|---|--------|-------------|---------|
| 1 | Scenario ID | Unique ID | TS-API-001, TS-UI-001, TS-DB-001 |
| 2 | Scenario Description | What is being tested | "Upload valid forecast file with all required columns" |
| 3 | AC Mapping | Acceptance Criteria ID(s) | AC-1 |
| 4 | AC Text | Full AC text | "Forecast file must contain required columns..." |
| 5 | **Test Type** | **Type from scope** | **API / UI / Database / BusinessLogic / Integration** |
| 6 | **Category** | **Scenario category** | **HappyPath / ErrorHandling / Boundary / Security / Performance** |
| 7 | Priority | Criticality | Critical / High / Medium / Low |
| 8 | Preconditions | Setup requirements | "User is authenticated, Site Editor is accessible" |
| 9 | Expected Result | What should happen | "File uploads successfully, returns 200 OK" |
| 10 | Test Data | Data needed | "Valid Excel with pod, dc, loadday, loadhour columns" |

**Changed from prior version:**
- Column 5 was "Test Type" holding values like "API / Security / Performance"
- Now split into column 5 "Test Type" (scope axis) and column 6 "Category" (concern axis)
- This allows Phase 5 to carry Type forward without losing Category

### Step 7: Generate Scenario IDs

ID prefixes by **Type** (scoped):
- **TS-API-###**: API scenarios (only if `"API" in selected_types`)
- **TS-UI-###**: UI scenarios (only if `"UI" in selected_types`)
- **TS-DB-###**: Database scenarios (only if `"Database" in selected_types`)
- **TS-BL-###**: Business Logic scenarios (only if `"BusinessLogic" in selected_types`)
- **TS-INT-###**: Integration scenarios (only if `"Integration" in selected_types`)

Legacy prefixes by **Category** (unscoped, deprecated):
- **TS-HP-###**: Happy Path (use Type-based prefix + Category=HappyPath instead)
- **TS-ERR-###**: Error handling (use Type-based prefix + Category=ErrorHandling instead)

**Prefer Type-based prefixes.** They are self-documenting and validate scope at a glance.

### Step 8: Write Excel File

```python
import openpyxl
from openpyxl.styles import Font, Alignment, PatternFill

# Create workbook
wb = openpyxl.Workbook()
ws = wb.active
ws.title = "Test Scenarios"

# Define headers (10 columns)
headers = [
    "Scenario ID",
    "Scenario Description",
    "AC Mapping",
    "AC Text",
    "Test Type",       # NEW: scope axis (API/UI/Database/BusinessLogic/Integration)
    "Category",        # NEW: concern axis (HappyPath/ErrorHandling/Boundary/Security/Performance)
    "Priority",
    "Preconditions",
    "Expected Result",
    "Test Data"
]

# Write headers with formatting
header_fill = PatternFill(start_color="4472C4", end_color="4472C4", fill_type="solid")
header_font = Font(bold=True, color="FFFFFF")

for col_idx, header in enumerate(headers, 1):
    cell = ws.cell(row=1, column=col_idx)
    cell.value = header
    cell.font = header_font
    cell.fill = header_fill
    cell.alignment = Alignment(horizontal="center", vertical="center")

# Write scenario rows
for row_idx, scenario in enumerate(scenarios, 2):
    ws.cell(row=row_idx, column=1).value = scenario['id']
    ws.cell(row=row_idx, column=2).value = scenario['description']
    ws.cell(row=row_idx, column=3).value = scenario['ac_id']
    ws.cell(row=row_idx, column=4).value = scenario['ac_text']
    ws.cell(row=row_idx, column=5).value = scenario['test_type']    # Type (scoped)
    ws.cell(row=row_idx, column=6).value = scenario['category']     # Category
    ws.cell(row=row_idx, column=7).value = scenario['priority']
    ws.cell(row=row_idx, column=8).value = scenario['preconditions']
    ws.cell(row=row_idx, column=9).value = scenario['expected_result']
    ws.cell(row=row_idx, column=10).value = scenario['test_data']
    
    # --- SCOPE VALIDATION: every emitted row must be in scope -------------------
    if scenario['test_type'] not in selected_types:
        raise ScopeContractError(
            f"SCOPE VIOLATION: scenario {scenario['id']} has Type={scenario['test_type']}, "
            f"which is not in selected_types={selected_types}. This is a generation bug."
        )
    ws.cell(row=row_idx, column=4).value = scenario['ac_text']
    ws.cell(row=row_idx, column=5).value = scenario['test_type']
    ws.cell(row=row_idx, column=6).value = scenario['priority']
    ws.cell(row=row_idx, column=7).value = scenario['preconditions']
    ws.cell(row=row_idx, column=8).value = scenario['expected_result']
    ws.cell(row=row_idx, column=9).value = scenario['test_data']

# Auto-size columns
for column in ws.columns:
    max_length = 0
    column_letter = column[0].column_letter
    for cell in column:
        if cell.value:
            max_length = max(max_length, len(str(cell.value)))
    adjusted_width = min(max_length + 2, 60)  # Cap at 60
    ws.column_dimensions[column_letter].width = adjusted_width

# Enable text wrapping
for row in ws.iter_rows(min_row=2):
    for cell in row:
        cell.alignment = Alignment(wrap_text=True, vertical="top")

# Save workbook
wb.save(paths.test_scenarios)
```

## Scenario Generation Patterns

### Pattern 1: API Endpoint Scenarios

For each API endpoint, generate:
```
- TS-HP-XXX: Valid request with all required parameters
- TS-API-XXX: Valid request with optional parameters
- TS-ERR-XXX: Missing required parameter
- TS-ERR-XXX: Invalid parameter type
- TS-ERR-XXX: Invalid parameter value
- TS-SEC-XXX: Missing authentication token
- TS-SEC-XXX: Invalid/expired token
```

### Pattern 2: Database Operation Scenarios

For each table/column constraint:
```
- TS-HP-XXX: Insert valid record
- TS-ERR-XXX: Violate NOT NULL constraint
- TS-ERR-XXX: Violate UNIQUE constraint
- TS-ERR-XXX: Violate FOREIGN KEY constraint
- TS-INT-XXX: Verify database state after operation
```

### Pattern 3: Business Rule Scenarios

For each validation rule:
```
- TS-HP-XXX: Rule is satisfied
- TS-ERR-XXX: Rule is violated (boundary - 1)
- TS-API-XXX: Rule boundary value (min/max)
- TS-ERR-XXX: Rule is violated (boundary + 1)
```

### Pattern 4: UI Flow Scenarios

For each user workflow:
```
- TS-UI-XXX: Complete workflow successfully
- TS-UI-XXX: Cancel workflow mid-flow
- TS-ERR-XXX: Submit with validation errors
- TS-UI-XXX: Navigation between steps
```
